3. Description of the Selected Encryption Method

CipherLab implements the Vigenère cipher, a classical polyalphabetic substitution cipher. Instead of shifting every letter by a fixed amount (as in the Caesar cipher), each letter of the keyword determines how many positions its message letter is shifted: A = 0, B = 1, C = 2, and so on up to Z = 25. The keyword repeats across the entire message, so a single keyword produces 26 different shift alphabets.

Because every shift is undone by the exact opposite shift, the method is fully reversible: encrypting with a keyword, then decrypting the result with the same keyword, recovers the original message exactly.

4. Explanation of the Encryption Function

The engine lives in Cipher.php. Both actions share one transformation function, transform(), which is called with direction +1 for encryption and −1 for decryption.

Input

  • $text — the message to transform (any printable text).
  • $keyword — the secret keyword (letters A–Z only, case-insensitive; automatically uppercased).

Key and settings

  • The keyword must contain letters only; the input is rejected otherwise.
  • The keyword repeats endlessly ($keyIndex % $keyLength) for as long as there are letters to shift.
  • Only A–Z and a–z characters are encrypted; digits, spaces, and punctuation pass through unchanged.
  • Letter case is preserved (uppercase and lowercase are encoded with separate base values).

Transformation steps

encrypt(string $text, string $keyword): string calls transform($text, $keyword, 1), which:

  1. Validates the keyword (letters A–Z only — an empty or invalid keyword throws an exception).
  2. Reads the message letter by letter in a loop.
  3. Computes the shift from the current keyword letter: ord('K') − ord('A') = 10.
  4. Shifts the letter forward by that amount with wrap-around using modulo 26 arithmetic, keeping its original case.
  5. Advances the key index only when a letter was shifted; non-letters skip this step.

Core code (actual implementation)

$base    = $isUppercase ? 65 : 97;
$shift   = ord($normalizedKey[$keyIndex % $keyLength]) - 65;
$shifted = ($code - $base + ($direction * $shift) + 26) % 26;
$result .= chr($base + $shifted);
$keyIndex++;

$direction is +1 when encrypting and −1 when decrypting; the added 26 keeps the operand positive so a single formula serves both directions.

Output

The ciphertext string — same length as the input, with letters substituted and every other character preserved exactly as typed.

5. Explanation of the Decryption Function

decrypt(string $text, string $keyword): string calls the same shared engine with direction −1, which subtracts each keyword letter's shift instead of adding it. Since every encryption shift is added modulo 26, subtracting the identical shift (with the same key-advance schedule) undoes it exactly.

ActionDirectionFormulaEffect
Encrypt+1(Letter − Base + Shift + 26) mod 26Moves forward through the alphabet
Decrypt−1(Letter − Base − Shift + 26) mod 26Moves backward through the alphabet

The + 26 term prevents negative values when subtracting shifts that are larger than the letter's position (e.g. 9 − 24 = −15; −15 + 26 = 11 → L), so the formula never produces an invalid character. Non-letters are copied through untouched, and the keyword advances at the same positions as during encryption — an essential requirement, since a desynchronized key would corrupt the message.

Known limitations

  • Educational only: the Vigenère cipher is a historical method and offers no meaningful security for modern sensitive data.
  • Pattern leakage: a repeating keyword can be broken on longer texts through statistical analysis (e.g. the Kasiski examination).
  • Letters only: digits, spaces, and punctuation are left visible, revealing sentence structure and word boundaries.
  • Strict keyword rules: the keyword accepts English letters A–Z only, with no digits or symbols.
  • Text-only: the tool processes plain text strings; binary files such as images or PDFs are not supported.
